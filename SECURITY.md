# Security Policy

## Supported versions

Mergelio has no auto-updater, so fixes ship as a new release you download
yourself. Only the latest release receives security fixes.

| Version | Supported |
| --- | --- |
| 1.4.x | Yes |
| < 1.4 | No — upgrade to the latest [release](https://github.com/senseyman/mergelio/releases) |

## Reporting a vulnerability

**Do not open a public issue for a vulnerability.**

Report it privately through GitHub: go to the
[Security tab](https://github.com/senseyman/mergelio/security/advisories/new)
of this repository and choose **Report a vulnerability**. That opens a private
advisory visible only to you and the maintainer.

Include what you have:

- Affected version, OS and OS version.
- What an attacker can do — read a file outside the repository, run a command,
  recover a credential.
- Steps to reproduce, ideally a minimal repository or a sequence of actions in
  the app.
- Whether it needs the user to open a hostile repository, click something, or
  neither.
- Any proof-of-concept you already have.

Please leave logs, screenshots and repository paths in only if you are
comfortable sharing them; a private advisory is still a hosted service.

### What to expect

- **Acknowledgement** within 7 days.
- **An assessment** — accepted, needs more information, or out of scope — within
  14 days, with reasoning either way.
- **A fix** in the next release once the severity is agreed. High-severity
  issues get an out-of-band release.
- **Credit** in the release notes and the advisory under whatever name or handle
  you prefer, unless you would rather stay anonymous.

Please give a reasonable window — 90 days, or until a fix ships if that is
sooner — before disclosing publicly. This is a single-maintainer project; if a
report goes unanswered past the windows above, ping the issue tracker without
details ("I sent a private advisory on <date>") rather than posting the report.

## Scope

Mergelio is a desktop app that drives your local `git`. There is no server, no
account and no backend to attack; the interesting surface is what the app does
on your machine and with repositories it opens.

**In scope:**

- Path escapes — any operation that reads, writes or deletes outside the
  repository the user opened.
- Argument or command injection into a `git` invocation, the embedded terminal,
  or `ssh-keygen`, including through branch names, remote names, tags, file
  paths, submodule entries or `.git` config values that come from a cloned
  repository.
- Credential or key material leaking into logs, telemetry, the SQLite store, or
  anywhere on disk outside the OS keychain and `ssh-agent`.
- Telemetry scrubbing failures — file paths, e-mail addresses, remote names or
  URLs escaping the scrubber when telemetry is enabled.
- Data loss from destructive operations that bypass the confirmation gate, the
  auto-stash, or the operation journal.
- Anything that makes a hostile repository execute code on clone, open or
  browse, beyond what `git` itself would do.
- Release integrity — the build pipeline, the published artifacts, or the
  `SHA256SUMS.txt` signature chain.

**Out of scope:**

- Behaviour inherited from `git` itself. Mergelio shells out on purpose so it
  matches your terminal, hooks and config. Report those to the
  [Git project](https://git-scm.com/community).
- Repository hooks running when you invoke an operation that runs hooks. That is
  the intended contract with your own `git` config.
- Vulnerabilities requiring an attacker who already has local code execution or
  filesystem access as your user.
- Unsigned Windows installers and SmartScreen warnings — known, tracked, and
  documented in the [README](README.md#installation).
- Missing hardening flags with no demonstrated impact.
- Reports generated by a scanner with no analysis of exploitability.

## Verifying a release

Every release ships `SHA256SUMS.txt` and a detached OpenPGP signature,
`SHA256SUMS.txt.asc`, covering every file in that release.

```bash
gpg --keyserver keys.openpgp.org --recv-keys 817229DD049EDD81D4D8FB2B080226BF36A5B807
gpg --verify SHA256SUMS.txt.asc SHA256SUMS.txt
sha256sum --check --ignore-missing SHA256SUMS.txt
```

Fedora packages carry the same signature in the RPM header. See
[Verifying a download](README.md#verifying-a-download) for the full procedure.

If a signature does not verify, treat the download as hostile and report it
through the private advisory process above.

## Security-relevant design

Useful context when assessing a finding:

- Mergelio never reimplements git; it invokes the `git` binary on your `PATH`.
- Credentials are handled by your existing git credential helper and
  `ssh-agent`. The app stores no passwords or tokens.
- SSH keys are generated by the system `ssh-keygen`, so key material stays in OS
  tooling.
- Telemetry is opt-in and off by default; when enabled, values are scrubbed of
  file paths, e-mail addresses, remote names and URLs before leaving the
  machine.
- Settings, recents, open tabs and the operation journal live in a local SQLite
  database in the OS application-support directory. Logs are written next to it
  and never leave the machine.
- Every mutating operation is written to a durable journal before it runs, so an
  interrupted operation is reported on the next launch.
