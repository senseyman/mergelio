# New

## Highlights

- **What's new tab.** After an update, Mergelio shows what changed in the new version.
- **Select several files.** Stage, unstage, stash or discard many files in the Changes panel at once.
- **Cherry-pick several commits.** Pick a run of commits in the graph and apply them in one step.
- **Author and date filters.** Search the whole history by author or date, not just the commits already loaded.

## What's new tab

- After an update, the first launch opens a **What's new** tab with the notes for every version since the one you last ran.
- It shows once per version. You can reopen it at any time with "What's new" in the command palette (⌘K).

## Changes panel: multi-select

- Cmd-click (Ctrl-click off macOS) adds or removes a file. Shift-click picks the run of files from the last one you clicked. A plain click still picks one file and opens its diff.
- A selection belongs to one list, so a partly staged file is picked on one side only.
- With two or more files picked, a bar offers stage or unstage, stash, discard and clear. A selected row's checkbox and right-click menu act on the whole selection.
- Discarding a selection asks for confirmation and is one undo entry.
- The stash dialog can open on a selection, with only those files ticked.
- In tree view, a folder row has a checkbox and a right-click entry that stage or unstage every file under it, including files in collapsed folders.
- Selected rows are announced as selected by screen readers.

## Ignore rules

- Right-click an untracked file and choose **Ignore…** to ignore that file, every file with its extension, or its folder.
- The rule goes to the root `.gitignore`, the nearest nested `.gitignore`, or `.git/info/exclude`. The dialog shows the exact line first.
- Mergelio only adds to ignore files and never rewrites them. Nothing is staged, and a rule that is already there is not added twice.
- Undo restores the file exactly as it was, or removes it if the action created it.

## Cherry-pick several commits

- Cmd-click (Ctrl-click off macOS) adds or removes a commit in the graph. Shift-click picks the run from the first one. A plain click clears the picks.
- With two or more commits picked, a bar above the graph and the context menu offer **Cherry-pick** and **Cherry-pick without committing**.
- Commits are applied oldest first, whatever order you clicked them in.
- The whole run is one undo entry. A conflict pauses it in the merge tool, labelled with the commit it stopped on, and continuing applies the rest.
- Without committing, the changes are left staged for you to commit. If a conflict happens, the whole run is rolled back, so this mode needs a clean tracked tree.
- Merge commits can't be picked together. Cherry-pick them on their own to choose a parent.

## Apply patch

- "Apply patch…" in the command palette takes a `.patch` or `.diff` file, or a `git format-patch` mailbox.
- Before applying, it lists the files the patch touches and each message's subject, and it checks that the patch fits.
- Choose how to apply it: to the working tree, to the working tree and the index, or as a 3-way merge that may leave conflicts. Only the options that will work are offered.
- Nothing is committed. A mailbox's messages and authors are not applied.
- Applying to the working tree or the index can be undone. A 3-way merge can't.

## Diff options

- The whole-file button in the diff header is now a diff options menu. Show 3, 5 or 10 lines of context, or the whole file.
- Show whitespace, ignore changes in whitespace, or ignore all whitespace. Your choice is remembered.
- While whitespace is hidden, staging and discarding single hunks or lines is turned off, with a notice saying why.
- A file whose only change is whitespace now reads "Only whitespace changed".

## Blame options

- The Blame tab has an options menu. Ignore whitespace, follow lines moved within the file, or follow lines moved from other files.
- It can skip the revisions listed in the repository's ignore-revs file (`blame.ignoreRevsFile`, or `.git-blame-ignore-revs` at the repository root). This shows only when the file exists, and is on by default.
- The menu icon lights up whenever blame reads differently from plain git.
- Blame now also works in repositories that use SHA-256 object names.

## Clone options

- The clone dialog has a collapsible options section. Choose a shallow clone with a depth, a blobless clone that fetches file contents on demand, a branch to check out (optionally only that branch), and whether to include submodules.
- An invalid depth or branch name disables **Clone** and the reason stays visible even when the section is collapsed.
- A shallow repository shows a **Shallow** badge in the sidebar header. Click it to fetch the full history. You can cancel it.

## Search filters

- The search bar has a **Date** chip with presets and a custom range, and an author field. The author matches name or email, ignoring case.
- Filters are answered by git over the full history, so matches beyond the loaded commits are found. A "+N" button loads them into the graph.
- Dates compare the author date, which a rebase doesn't change.
- **Hide merges** applies to these results too.

# Fixed

- Searching by author only matched the names of commits already loaded. An email never matched.
- The app always came back on the last tab after a restart. It now reopens the tab you had selected.
- Closing the active tab inside an empty group could leave nothing selected, and that was saved.
- A missing or broken ignore-revs file made every blame fail. Blame now leaves the file out, and the menu names the file and the bad line.
- Text with non-ASCII characters, such as file names and credentials, could be garbled on Windows when passed to git.
- A failed file write during an undoable action could be reported as an interrupted operation on the next launch.
