# New

- **Create a pull request from a branch.** Right-click a branch in the sidebar and choose **Create pull request…** (**Create merge request…** on GitLab). The forge's own new-request page opens in your browser for that branch, and nothing is created until you submit it there. No token is needed. A branch origin doesn't have yet asks you to push it first.
- **Check out a pull request.** Right-click a row in **Pull requests** (**Merge requests** on GitLab) and choose **Check out locally as pr/12** (**mr/12** on GitLab) to bring the request's commits into that branch and switch to it, requests from forks included. Once you're on it, the entry reads **Update pr/12**. The branch only ever moves forward: if the request was force-pushed and your copy has commits it no longer has, Mergelio asks before replacing it. One undo puts the branch back and returns you to where you were. No commit is ever made. A plain click on the row still opens it in your browser.
- **GitHub Enterprise and self-managed GitLab.** Preferences → Credentials now lists your **forge accounts**, as many as you need. **Add account…** asks for GitHub or GitLab, then the public service or your own server's `https://` address, then a personal access token, which is checked against that server before it is kept. Once a server is added, its repositories show the pull request and issue sections too. Each account can **Replace token…** or **Disconnect**, and a self-hosted server can be removed. Tokens stay in your git credential helper, as before. Servers installed under a sub-path, such as `https://example.com/gitlab`, are not supported yet.
