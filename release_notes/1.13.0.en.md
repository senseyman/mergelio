# New

## Highlights

- **Git notes.** Attach a note to any commit without changing it, and share notes with a remote.
- **Open in your tools.** Open a file in your editor, or in your diff tool or merge tool, straight from Mergelio.
- **Signed tags.** Sign a tag when you create it, and read each tag's message in commit details.
- **Repository settings.** Edit a repository's git config from Preferences → Repository.
- **Messages in your language.** Notifications, progress and undo labels now follow the app language.

## Git notes

- Right-click a commit in the graph and choose **Add note…** or **Edit note…**. Saving a note empty removes it, and **Remove note** removes it directly.
- Commit details show the commit's note, with buttons to edit, copy and remove it.
- Adding, editing and removing a note can be undone.
- Notes stay on this machine until you share them. A remote's menu in the sidebar, the command palette and the **Fetch** menu offer **Push notes** and **Fetch notes**, and the Push dialog has **Also push notes**.
- Fetched notes are merged with yours, so two people can add notes to the same repository. Where both of you noted the same commit, both texts are kept.
- Turn on **Fetch notes with every fetch** in Preferences, or tick it in the **Fetch** menu, to bring in each remote's notes whenever you fetch, auto-fetch included. It is off by default.
- Notes never appear as commits in the graph or in search results.

## Open in editor, diff tool and merge tool

- **Open in editor** is available in the Changes panel, commit details, the diff view and the Files browser. From the unstaged side of a diff, the file opens at the first change.
- Choose the editor in Preferences → General → **Open files with**: the system default app, VS Code, IntelliJ IDEA, or a custom command. A custom command can use `{file}` and `{line}`, and is run directly, never through a shell.
- **Open in diff tool** runs `git difftool` with the tool you set in git config, for working-tree changes, a commit or a comparison. Up to four can be open at once.
- **Open in merge tool** runs `git mergetool` for a conflicted file. When the tool reports success, git stages the file and Mergelio stops there, so you still finish the merge yourself. Resolving the last file ends the session as **Resolve** does.
- If no diff tool or merge tool is set, Mergelio says so and shows the git command that sets one.
- Editors and tools are found even when Mergelio is started from the Finder or the Dock.

## Signed tags

- The create-tag dialog has **Sign tag** and an optional **Signing key**. A signed tag is always annotated.
- Sign tag starts on when your git config asks for signed tags (`tag.gpgSign`, or `commit.gpgsign`).
- The active profile's identity is used as the tagger, as it is for commits. Signing waits for your passphrase, and the busy bar has a **Cancel** button.
- Commit details show each annotated tag's tagger, date and message next to its signature check. A tag that can't be read says so instead of disappearing.

## Repository settings

- Preferences has a new **Repository** tab for the repository on screen. It covers name and email, pull rebase, setting the upstream on first push, pruning on fetch, line-ending conversion, **Sign commits** and rerere.
- Each row shows the value git uses and where it comes from: system, global, this repository, worktree or command line. Hover to see the file.
- Changes are saved to **This repository** unless you pick **Global**. **Inherit** removes the value from the chosen place, so the one from a wider scope applies again.
- Where Mergelio overrides a setting, the tab says so. For example, the active profile's identity is used for commits made in Mergelio.

## Messages in your language

- Notifications, busy-bar labels and undo labels for every action, cloning, creating a repository and generating an SSH key now follow the app language. Before, they were always in English.
- Switching the language applies to the next message.
- Text that git itself prints is shown as git wrote it.

# Fixed

- With `tag.gpgSign` set in git config, creating a lightweight tag failed, and annotated tags were signed even when you didn't ask. A tag is now signed only when **Sign tag** is on.
- Undoing a tag deletion now brings back the original tag with its message, tagger and signature.
